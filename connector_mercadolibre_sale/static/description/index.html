Mercado Libre Connector - Sales

Import Mercado Libre orders, cart packs, and shipments into Odoo.

One Mercado Libre order becomes one sales order. Orders that share a pack id stay linked. Shipment status is stored on its own binding and linked to the delivery when one exists. Paid orders stay in draft and enter the automatic workflow configured on the backend.

Important

This is an alpha version, the data model and design can change at any time without warning. Only for development or testing purpose, do not use in production. More details on development status

Installation

Install connector_mercadolibre_product first, then this module.

This module also depends on sale_stock, delivery, stock_delivery, sale_automatic_workflow, sale_automatic_workflow_job, and sale_exception.

Configuration

  1. Open the Mercado Libre backend and the page Sales.
  2. Choose an Automatic Workflow. Import orders stays available only when a workflow is set. Confirmation, invoicing, and delivery validation stay in sale_automatic_workflow.
  3. Set the sales team and the fiscal position copied onto imported orders.
  4. Choose service products for the shipping cost and the marketplace fee.
  5. Optionally set a tracking carrier. Tracking numbers are exported only for the seller-provided modes custom and me1.
  6. Map seller warehouses on the Catalog page before enabling Export stock. An unmapped seller logistic type (drop_off, xd_drop_off, cross_docking, self_service) raises a sale exception. Fulfillment stock is never pushed.

Usage

Paid orders import as draft sales orders and take the automatic workflow from the backend. A cart is several sales orders with the same pack id. The Pack smart button opens the other orders.

A missing SKU is a note on the sales order. The exception Mercado Libre missing SKU blocks confirmation until the listing is matched and the order is imported again.

Cancelling a Mercado Libre order cancels that sales order when no delivery is done. The other orders in the pack are left as they are.

Shipment notifications update the shipment binding. A done delivery on a custom or me1 shipment enqueues one tracking export. me2 and fulfillment shipments store the tracking number and do not send one.

A payments notification updates the payment status of the existing order. It does not create a second sales order.

The reconciliation cron and a repeated orders_v2 notification share one import job per order.

Development

Handlers set _topic to orders_v2, shipments, or payments and _apply_on to mercadolibre.notification. The core dispatcher matches _topic. _apply_on has to be an Odoo model, so the topic name is not stored there.

Line builders share the usage sale.order.line.builder. The importer loads them with many_components and sorts by _sequence (product 10, shipping 20, fee 30). Add another builder for a coupon or a local tax without changing the importer.

Odoo 19 rejects a sales order line that has neither a product nor a display type. An unmatched item is a line_note with mercadolibre_unmatched set. The exception rule exception_missing_sku reads that flag and blocks confirmation.

The status mapper usage is status.mapper. Override apply for a different confirmation or cancellation rule. This module leaves paid orders in draft.

Tracking export is the stock picking listener, not the shipment importer. The identity keys are:

  • meli:orders:{backend_id} for the batch
  • meli:order:{backend_id}:{order_id} for one order
  • meli:shipment:{backend_id}:{shipment_id} for one shipment
  • meli:payment:{backend_id}:{resource} for a payment notification
  • meli:tracking:{backend_id}:{shipment_id} for a tracking export

Buyers are matched only through mercadolibre.res.partner. The binder does not search res.partner by name.

Known issues / Roadmap

  • Coupon and discount lines.
  • Mercado Pago settlement detail beyond the payment status.
  • Invoice fiscal data for each country.
  • Pack-level shipping quotes when Mercado Libre splits a cart across shipments.
